## 1. บทนำ

### 1.1 วัตถุประสงค์
กำหนดสิ่งที่ SEMS ต้องทำ (Functional Requirement) อย่างละเอียดพอสำหรับออกแบบ พัฒนา และทดสอบ โดยทุกข้อ trace กลับไปยัง Scope, Use Case และ Business Rule ได้

### 1.2 วิธีอ่าน
- **รหัส:** `FR-<โมดูล>-<ลำดับ>`
- **คอลัมน์ Trace:** `S` = ข้อใน Scope, `UC` = Use Case, `BR` = Business Rule, `MSG` = ข้อความแจ้งเตือนใน BR หัวข้อ 11
- **คำว่า "ต้อง"** = บังคับ; **เกณฑ์ตรวจรับ** = เงื่อนไขที่ใช้เขียน Test Case
- **สถานะพิเศษ:** `[ใหม่]` = ข้อกำหนดที่เพิ่มจากคำตอบรอบล่าสุด ซึ่งยังไม่อยู่ใน Scope/UC เดิม (ต้องแจ้งอาจารย์และปรับ Scope/UC) · `[TBD]` = รอออกแบบหรือรอยืนยัน
