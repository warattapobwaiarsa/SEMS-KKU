| Postcondition | ผู้ใช้อยู่ในระบบตามสิทธิ์ของบทบาท |

## ส่วนที่ 2: Use Case ของ Admin

### UC-A01 จัดการข้อมูลผู้ใช้งานและสถานะการใช้งานบัญชี
| หัวข้อ | รายละเอียด |
|---|---|
| Actor | Admin |
| คำอธิบาย | เพิ่ม แก้ไข ค้นหาผู้ใช้ เปิด/ปิดบัญชี และกำหนดหรือต่ออายุของ Evaluator |
| Precondition | Admin เข้าสู่ระบบแล้ว |
| Main Flow | 1. Admin ค้นหาหรือเลือกเพิ่มผู้ใช้<br>2. Admin กรอก/แก้ไขข้อมูล บทบาท และอายุบัญชีเป็นจำนวนวัน (สำหรับ Evaluator; ระบบคำนวณวันหมดอายุให้)<br>3. Admin เปิดหรือปิดสถานะบัญชีได้ (กรณีเปิดบัญชี Evaluator ที่ถูกปิดไปแล้วกลับมา ต้องกำหนดวันหมดอายุใหม่ทุกครั้ง)<br>4. ระบบตรวจสอบและบันทึก<br>5. ระบบแสดงผลลัพธ์ |
| Alternative | A1. ปิดบัญชี Evaluator ที่มี Evaluation Draft ในรอบ Open → ไม่อนุญาต และแจ้งเหตุผล<br>A2. เปิดบัญชี Evaluator ที่ถูกปิดโดยไม่กำหนดวันหมดอายุใหม่ → ไม่บันทึก |
| Business Rule | • บัญชี Admin ไม่มีวันหมดอายุ; บัญชี Evaluator ต้องกำหนดอายุการใช้งานเสมอ<br>• ปิดบัญชีที่มี Evaluation Draft ค้างอยู่ในรอบ Open ไม่ได้<br>• เมื่อบัญชีหมดอายุ ระบบ Auto-deactivate (หากมี Draft ดังกล่าวให้เลื่อนออกไปจนกว่า Evaluator จะ Submit หรือรอบเป็น Closed)<br>• บัญชี Expired-but-active แก้และ Submit ได้เฉพาะ Draft เดิม แต่เริ่มประเมินผู้สมัครใหม่ไม่ได้<br>• ต่ออายุบัญชีได้<br>• ไม่สามารถลบบัญชีผู้ใช้ (ปิดการใช้งานได้อย่างเดียว) |
| Postcondition | ข้อมูลผู้ใช้/สถานะ/อายุถูกอัปเดต |
| Audit Log | เพิ่ม/แก้ไข/เปิด/ปิดผู้ใช้ |

### UC-A02 จัดการข้อมูลรอบทุนการศึกษา
| หัวข้อ | รายละเอียด |
|---|---|
| Actor | Admin |
| คำอธิบาย | สร้าง แก้ไข และค้นหารอบทุนการศึกษา |
| Precondition | Admin เข้าสู่ระบบแล้ว |
| Main Flow | 1. Admin เลือกสร้างรอบใหม่หรือค้นหารอบ<br>2. Admin กรอก/แก้ไขข้อมูลรอบ<br>3. ระบบตรวจสอบและบันทึก (สถานะเริ่มต้น Draft) |
| Business Rule | • แก้ไขข้อมูลรอบได้เฉพาะสถานะ Draft (หลัง Open ไม่สามารถแก้)<br>• สถานะรอบ: Draft → Open → Closed<br>• ไม่สามารถลบรอบ |
| Postcondition | ข้อมูลรอบถูกบันทึก |

### UC-A03 จัดการเกณฑ์การประเมินและเกณฑ์ย่อย
| หัวข้อ | รายละเอียด |
|---|---|
| Actor | Admin |
| คำอธิบาย | สร้าง แก้ไข ค้นหาเกณฑ์/เกณฑ์ย่อย และเชื่อมเกณฑ์กับรอบทุน |
| Precondition | Admin เข้าสู่ระบบแล้ว<br>• การแก้ไขเกณฑ์/เกณฑ์ย่อย: ต้องไม่มีรอบทุนที่ใช้เกณฑ์นั้นอยู่ในสถานะ Open หรือ Closed<br>• การเลือก/เปลี่ยน/ถอดเกณฑ์ออกจากรอบ: รอบนั้นต้องอยู่ในสถานะ Draft |
| Main Flow | 1. Admin สร้างหรือค้นหาเกณฑ์<br>2. Admin กำหนดเกณฑ์ย่อย ประเภท (Scored / Non-scored text) คะแนนสูงสุด (เฉพาะ Scored) และกำหนดว่าอนุญาตให้ Evaluator บันทึก Comment หรือไม่ (เฉพาะ Scored)<br>3. Admin เชื่อมเกณฑ์กับรอบทุน (หรือเปลี่ยน/ถอด)<br>4. ระบบตรวจสอบและบันทึก |
| Alternative | A1. ผลรวมคะแนนสูงสุดของ Scored subcriteria ไม่เท่ากับ 100 หรือคะแนนสูงสุดข้อใดไม่ใช่จำนวนเต็ม 1–100 → ระบบแจ้งข้อผิดพลาดพร้อมผลรวมปัจจุบัน และไม่บันทึก<br>A2. เกณฑ์ถูกใช้ในรอบที่เปลี่ยนเป็น Open แล้ว → แก้ไม่ได้ ต้องสร้างเกณฑ์ใหม่แทน |
| Business Rule | • ผลรวมคะแนนสูงสุดของ Scored subcriteria ต้องเท่ากับ 100 (ไม่นับ Non-scored) ตรวจทุกครั้งที่ยืนยันบันทึก<br>• คะแนนสูงสุดแต่ละข้อเป็นจำนวนเต็ม 1–100<br>• 1 รอบทุนใช้ 1 เกณฑ์ และนำเกณฑ์เดียวกันกลับมาใช้ในรอบอื่นได้ทั้งชุด<br>• เกณฑ์ที่ยังไม่ถูกใช้ในรอบ Open/Closed แก้ไขได้<br>• เลือก/เปลี่ยน/ถอดเกณฑ์ออกจากรอบได้เฉพาะรอบ Draft |
| Postcondition | เกณฑ์และการเชื่อมกับรอบถูกบันทึก |
| Audit Log | เพิ่ม/แก้ไขเกณฑ์ |

### UC-A04 นำเข้าข้อมูลผู้สมัครจากไฟล์ Excel
| หัวข้อ | รายละเอียด |
|---|---|
| Actor | Admin |
| คำอธิบาย | นำเข้ารายชื่อและข้อมูลผู้สมัครเข้าสู่รอบทุนจากไฟล์ Excel (.xlsx) |
| Precondition | รอบทุนอยู่ในสถานะ Draft |
| Include | UC-A05 อ่านและตรวจสอบข้อมูล Excel |
| Main Flow | 1. Admin เลือกรอบและไฟล์ Excel<br>2. ระบบอ่านและตรวจสอบไฟล์ (UC-A05)<br>3. ระบบแสดง Preview แถวที่ valid / invalid พร้อมเหตุผลรายแถว (Citizen ID แสดงแบบปิดบังบางส่วน)<br>4. ระบบแสดงจำนวนแถว invalid และ Admin กดรับทราบ<br>5. Admin ยืนยันนำเข้า<br>6. ระบบนำเข้าเฉพาะแถวที่ valid (แทนที่ชุดข้อมูลผู้สมัครเดิมของรอบทั้งหมด)<br>7. ระบบลบไฟล์ชั่วคราว |
| Alternative | A1. ไฟล์ผิดรูปแบบ (ไม่ใช่ .xlsx / เกินขนาด / คอลัมน์บังคับไม่ครบ) → ระบบแจ้งและไม่นำเข้า<br>A2. ไม่มีแถวใดผ่านการตรวจสอบ → ไม่อนุญาตให้ยืนยันนำเข้า<br>A3. Admin ยกเลิกหลัง Preview → ไม่มีการนำเข้า และระบบลบไฟล์ชั่วคราว |
| Business Rule | • แถว invalid ไม่ถูกนำเข้า<br>• Admin ต้องรับทราบจำนวนแถว invalid ก่อนยืนยัน (กรณีมีแถว invalid)<br>• การนำเข้าแทนที่ชุดข้อมูลผู้สมัครเดิมของรอบทั้งหมด<br>• นำเข้า/แทนที่ในรอบ Open หรือ Closed ไม่ได้<br>• ข้อมูลผู้สมัครที่นำเข้าแล้วแก้ไขใน SEMS ไม่ได้ หากต้องแก้ให้แก้ที่ระบบทุนการศึกษาเดิมแล้วนำเข้าไฟล์ใหม่ (เฉพาะรอบ Draft)<br>• ระบบตรวจเฉพาะรูปแบบและเงื่อนไข ไม่ตรวจความถูกต้องของเนื้อหาเทียบระบบเดิม |
| Postcondition | ข้อมูลผู้สมัครของรอบถูกนำเข้า |
| Audit Log | Import |

### UC-A05 อ่านและตรวจสอบข้อมูล Excel *(Included — System Function 3)*

|---|---|
| Actor | System |

| Main Flow | 1. ระบบอ่านไฟล์<br>2. ระบบตรวจรูปแบบและข้อมูลที่จำเป็นของแต่ละแถว (รหัสนักศึกษาไม่ซ้ำในไฟล์, GPA 0.00–4.00, Citizen ID เป็นตัวเลข 13 หลัก)<br>3. ระบบจำแนกแถว valid / invalid พร้อมเหตุผล (ไม่แสดงหรือบันทึก Citizen ID เต็มในผลตรวจ/ข้อผิดพลาด)<br>4. ระบบส่งผลกลับให้ UC-A04 |

### UC-A06 ค้นหาและดูรายชื่อผู้สมัครในรอบทุนการศึกษา
| หัวข้อ | รายละเอียด |
|---|---|
| Actor | Admin |
| คำอธิบาย | ค้นหารอบ กรอง และดูรายชื่อผู้สมัครในรูปแบบตาราง (View-only) เพื่อตรวจทานความครบถ้วนของข้อมูลที่นำเข้า |
| Precondition | Admin เข้าสู่ระบบแล้ว; มีรอบที่นำเข้าผู้สมัครแล้ว |
| Main Flow | 1. Admin ค้นหาและเลือกรอบด้วยรหัสรอบทุนการศึกษา<br>2. Admin กรองรายชื่อด้วยรหัสนักศึกษา ชื่อ-นามสกุล หรือคณะ<br>3. ระบบแสดงจำนวนผู้สมัครทั้งหมดในรอบ และตารางรายชื่อ (รหัสนักศึกษา, ชื่อ-นามสกุล, คณะ, สาขา, ชั้นปี, GPA) |
| Business Rule | • ดูได้ในทุกสถานะรอบ (Draft, Open, Closed)<br>• ดูได้อย่างเดียว ไม่อนุญาตให้แก้ไข เพิ่ม หรือลบข้อมูลผู้สมัคร<br>• ไม่แสดง Citizen ID / เบอร์โทร / อีเมล / ข้อมูลประกอบการพิจารณา |
| Postcondition | ไม่มีการเปลี่ยนแปลงข้อมูล |

### UC-A07 เปิดและปิดรอบทุนการศึกษา
| หัวข้อ | รายละเอียด |
|---|---|
| Actor | Admin |
| คำอธิบาย | เปลี่ยนสถานะรอบ Draft → Open และ Open → Closed |
| Precondition | Admin เข้าสู่ระบบแล้ว |
| Main Flow (เปิดรอบ) | 1. Admin เลือกรอบ Draft และสั่งเปิด<br>2. ระบบตรวจสอบความพร้อมก่อนเปิด: ข้อมูลหลักของรอบครบถ้วน, มีผู้สมัครอย่างน้อย 1 คน, มีเกณฑ์ที่เชื่อมกับรอบ 1 เกณฑ์ และผลรวมคะแนนสูงสุดของ Scored subcriteria เท่ากับ 100<br>3. ระบบแสดงจำนวนแถว invalid จากการนำเข้าครั้งล่าสุดให้ Admin รับทราบ (ไม่ใช่เงื่อนไขห้ามเปิดรอบ)<br>4. ระบบเปลี่ยนสถานะเป็น Open และล็อกข้อมูลหลักของรอบ ข้อมูลผู้สมัคร และเกณฑ์ที่ใช้ |
| Main Flow (ปิดรอบ) | 1. Admin เลือกรอบ Open และสั่งปิด<br>2. ระบบตรวจว่ามีผู้สมัครที่ไม่มี Evaluation สถานะ Submitted เลยหรือไม่<br>3. หากมี ระบบแสดงจำนวนและรายชื่อ (รหัสนักศึกษา, ชื่อ-นามสกุล) และ Admin กดรับทราบ (acknowledge); หากไม่มี ปิดรอบได้ทันที<br>4. ระบบเปลี่ยนสถานะเป็น Closed; Evaluation ที่ยังเป็น Draft ถูกล็อก ไม่นำไปคำนวณ และยังเก็บไว้ในระบบ |
| Alternative | A1. ไม่ผ่านการตรวจความพร้อม → ไม่เปิดรอบ และแจ้งเหตุผล<br>A2. Admin ไม่รับทราบรายชื่อผู้สมัครที่ไม่มี Submitted → ไม่ปิดรอบ |
| Business Rule | • สถานะรอบเปลี่ยนได้ทางเดียว (Draft → Open → Closed) ย้อนกลับไม่ได้<br>• ผู้สมัครที่ไม่มี Submitted เมื่อปิดรอบ ได้คะแนนสุดท้าย 0.00 และรับทุนไม่ได้<br>• เมื่อ Closed แล้ว แก้ไขหรือ Submit ผลการประเมินไม่ได้ |
| Postcondition | รอบอยู่ในสถานะ Open หรือ Closed |
| Audit Log | เปลี่ยนสถานะรอบ (กรณีปิดรอบ บันทึกจำนวนผู้สมัครที่ยังไม่มีผลการประเมินซึ่ง Admin รับทราบ) |

### UC-A09 จัดการผลการจัดสรรทุนการศึกษา

Admin เพิ่ม/แก้ไขสถานะการได้รับทุนและจำนวนเงินรายบุคคล<br>3. ระบบตรวจสอบงบประมาณและผลจัดสรร (UC-A10)<br>4. ระบบบันทึกและคำนวณยอดจัดสรรรวม/งบคงเหลือใหม่<br>5.
