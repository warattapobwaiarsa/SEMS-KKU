# SEMS — Non-Functional Requirement Specification (NFR)

**ฉบับ:** 0.1 (ร่าง) — 3 ต.ค. 2569 · เอกสารคู่กับ `sems-functional-requirements.md`
**แนวทาง:** ISO/IEC 29110 · หมวดคุณลักษณะอ้างอิงมุมมองคุณภาพซอฟต์แวร์ (ISO/IEC 25010)

**หมายเหตุสำคัญ:** Scope และ BR ระบุข้อกำหนด non-functional ไว้ค่อนข้างน้อย รายการที่ไม่มีที่มาจาก Scope/BR ผมทำเครื่องหมาย `[ASM]` (สมมติฐานเพื่อให้ตรวจรับได้) หรือ `[TBD]` (ต้องให้ทีม/อาจารย์/มหาวิทยาลัยกำหนดค่า) อย่าถือว่าเป็นข้อตกลงแล้ว

## วิธีอ่าน
- **รหัส:** `NFR-<หมวด>-<ลำดับ>`
- **Trace:** S = Scope, BR = Business Rule, FR = Functional Requirement ที่เกี่ยวข้อง

| NFR-PRF-03 | การคำนวณคะแนนและอันดับแบบ Realtime ต้องตอบสนองในเวลาที่ยอมรับได้ตามจำนวนผู้สมัครจริงของรอบ `[TBD: ยังไม่ทราบปริมาณผู้สมัคร]` | ทดสอบกับข้อมูลจำลองหลายขนาด | BR-IMP-17 · FR-SCR-05 |

## 10. ค่าพารามิเตอร์ที่ยังขาด (ต้องให้ทีม/มหาวิทยาลัยกำหนด)

1. เป้าหมาย uptime, backup (ความถี่, RPO/RTO)
2. จำนวนผู้ใช้พร้อมกันสูงสุดและปริมาณผู้สมัครต่อรอบ (ยังไม่ทราบตาม BR-IMP-17) ซึ่งกำหนดเป้า performance
3. เบราว์เซอร์และเวอร์ชันที่รองรับ
4. โปรโตคอล KKU SSO และขั้นตอนลงทะเบียน
5. อัลกอริทึมเข้ารหัสเลขบัตรและการจัดการกุญแจ
6. ข้อกำหนดการเข้าถึงสำหรับผู้พิการ (ต้องการหรือไม่)
